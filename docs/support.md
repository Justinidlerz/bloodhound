# Supported behavior and limits

The scanner reports static candidates for browser-window code. `completed` means the selected resources were processed without a recorded coverage gap; it does not prove complete runtime behavior or absence of pollution.

| Area            | Supported                                                                                                                                                             | Limits                                                                                                                           |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Inputs          | HTML/JS strings, content objects, files, HTTP(S), batch entries                                                                                                       | Strings are source text; no path/URL guessing                                                                                    |
| JavaScript mode | Classic scripts and ESM; HTML tag mode inference                                                                                                                      | Explicit `module` needed for standalone ESM; no auto mode                                                                        |
| Globals         | Direct/aliased property writes, definitions, deletes, updates, classic var/function and sloppy implicit writes                                                        | Global lexical collisions are not reported                                                                                       |
| Values          | Local aliases, object shapes, destructuring, finite strings, IIFEs                                                                                                    | No arbitrary calls, imported constant propagation or complete control-flow analysis                                              |
| DOM             | Document containers, direct selected-element insertion, document.write, common insertion methods                                                                      | Complex element wrappers and framework rendering may remain unknown                                                              |
| Styles          | Script-injected style/stylesheet nodes, document stylesheets, adoptedStyleSheets assignments, document inline styles                                                  | No CSS selector/property/keyframe/animation analysis; arbitrary CSSStyleSheet instance flows are not modeled                     |
| Cleanup         | Nodes: same-block or returned-function removal. Listeners: same event and handler reference anywhere in the file; receiver, capture and conditions do not participate | Pairing does not prove teardown executes. Inline anonymous callbacks are excluded; unresolved handler expressions are not paired |
| Dependencies    | Static/dynamic imports, HTML scripts, finite script/link URLs at insertion and modulepreload                                                                          | Iframe/srcdoc references are listed but not followed; Worker environments remain gaps; arbitrary dynamic URLs become gaps        |
| HTML            | Base URL, early import maps, script modes, template/data-block exclusion, CSS discovery                                                                               | SVG/MathML skipped with gaps; late import maps are ignored with gaps; not a full browser DOM tree builder                        |
| Source maps     | Comment directives, inline maps and offline/network map resources                                                                                                     | Invalid/unavailable maps omit original locations; map fetches have per-resource limits                                           |
| Locations       | Byte spans converted to UTF-16, inline origin and shortest source chain                                                                                               | Original positions require a valid source map                                                                                    |
| Execution       | Potential effects inside ordinary functions; bounded AST traversal                                                                                                    | No code execution, path feasibility proof, lifecycle proof or precision/recall guarantee                                         |

CSS dependencies appear in `dependencies` with `not-followed / css-not-analyzed`; they are not loaded recursively and do not produce source records. Explicit CSS entries are loaded and listed without rules. Ordinary SSR element styles are ignored; `<html style>` and `<body style>` are reported as informational findings.

Every standalone JavaScript entry is assumed to run in a browser window. Do not use the results to infer Node.js or Worker semantics. Iframe and `srcdoc` content belongs to a separate global object and is not scanned. Its dependency edge uses `not-followed / iframe-isolated-global`.

Limits are cooperative. `maxResources` caps resource nodes, `maxResourceBytes` caps each read, and `maxBytes` stops dispatch after observed total bytes exceed the threshold. In-flight jobs can overshoot the total byte budget. Parsing and an active network read are not instantly interruptible; `resourceTimeoutMs` bounds individual requests. Source-map bytes are subject to per-resource bounds but are not included in the manifest's resource-byte total.

Input snippets and URL query strings can contain sensitive information. Consumers control persistence and distribution of manifests. URL userinfo is rejected on input and removed on report serialization.
